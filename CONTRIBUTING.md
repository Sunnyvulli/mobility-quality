# Contributing and verification

Discuss a concrete bug or experiment before broad changes. Preserve original data, attribution, hashes, and existing user edits. Use a virtual environment and the pinned evaluation dependencies. Format Python with Black. Add a test that would fail before a behavior fix and pass after it. Run unittest and the evaluation when changing modeling, validation, or source data. Do not replace measurements manually or call a local prototype production deployed. Describe the problem, change, validation, and limits in a pull request.

The study includes three whole-day rolling-origin windows with an online weekly-lag baseline. Independent-source labels, seasonal calibration and realistic unknown-fault scenarios remain needed before expanding claims. Research manuscripts require author review before submission. Venue-specific authorship and disclosure requirements apply at submission.
